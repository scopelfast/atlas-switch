# E8.5 — Webhooks outbound Taskflow (MVP)

## Objectivo

Notificar sistemas externos quando tarefas são **criadas** ou **actualizadas**, via **POST** `application/json`, sem duplicar o mesmo evento para o mesmo endpoint (deduplicação persistente).

## Modelo de dados

| Tabela | Papel |
|--------|--------|
| `taskflow_webhooks` | URL HTTPS, nome, lista de eventos (`events` em CSV), `secret` opcional (HMAC-SHA256 do corpo, cabeçalho `X-Atlas-Webhook-Signature` em hex), `enabled`. |
| `taskflow_webhook_deliveries` | Uma linha por tentativa deduplicada: índice único `(webhook_id, dedupe_key)`; `http_status` e `error_message` após o POST. |

## Eventos (MVP)

- `task.created` — após `POST /api/taskflow/tasks` persistir a tarefa e o evento `CREATED` no histórico.
- `task.updated` — após `PATCH /api/taskflow/tasks` com alterações aplicadas (inclui ramo de tarefa terminal M7.5).

A lista em `events` no registo do webhook é **case-insensitive** e separada por vírgulas. Por omissão: `task.created,task.updated`.

## Payload JSON

```json
{
  "event": "task.created",
  "teamId": 1,
  "task": {
    "id": 42,
    "title": "…",
    "columnId": 3,
    "statusId": 5,
    "priority": "HIGH",
    "dueDate": "2026-04-20T00:00:00.000Z",
    "assigneeIds": [1, 2]
  },
  "sentAt": "2026-04-16T12:00:00.000Z"
}
```

## Idempotência

- `dedupe_key` inclui identificador estável do evento (ex.: `task.created:{taskId}:{taskflow_task_events.id}` ou `task.updated:{taskId}:{updatedAt_ms}`).
- Antes do `fetch`, insere-se em `taskflow_webhook_deliveries`; em conflito de unicidade **não** se reenvia (evita duplicados em retries ou corridas próximas no mesmo endpoint).

## Segurança e limites

- Só **HTTPS**; bloqueio básico de **localhost** e **RFC1918** / link-local no hostname (mitigação SSRF; não substitui allowlist enterprise).
- Máximo **`TASKFLOW_WEBHOOK_MAX_PER_TEAM` (5)** webhooks por time no MVP.
- O `secret` é armazenado em claro na BD — adequado a MVP; produção exigente deve usar segredos em cofre e rodar chaves.

## Notificações por e-mail

Os webhooks **não** substituem as notificações existentes (M6.7, etc.): são canal **adicional**; o memorial «não duplicar notificações» refere-se a não reenviar o **mesmo webhook** pela mesma chave de deduplicação.

## API

| Método | Rota | Descrição |
|--------|------|-----------|
| `GET` | `/api/taskflow/webhooks` | Lista (owner/admin/gestor); `hasSecret` sem revelar o segredo. |
| `POST` | `/api/taskflow/webhooks` | Cria (`name`, `targetUrl`, `secret?`, `events?`). |
| `PATCH` | `/api/taskflow/webhooks/[id]` | Actualiza campos parciais; `secret: ""` remove. |
| `DELETE` | `/api/taskflow/webhooks/[id]` | Remove. |

## Evolução (fora do MVP)

- Fila assíncrona (Redis/Rabbit) + worker — **ADR-0002** antes de introduzir dependências no caminho crítico.

## Zapier / Make (E8.14)

Guia operacional e URL assinada para JSON de exemplo: `Projeto/E8.14-zapier-make-taskflow.md` e manual `/manual/zapier-make`.
- Gatilhos por etiqueta, prazo, coluna específica (motor declarativo).
- Limites por plano SaaS (`team_plans` / `saas_plans`).
- Webhooks **inbound** (GitHub, etc.) → **E8.10**.
